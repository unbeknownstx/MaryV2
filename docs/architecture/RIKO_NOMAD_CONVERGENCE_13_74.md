# MaryV2 13.74 — Riko / NOMAD Convergence Surface

## Purpose

13.74 makes the already-connected intelligence, knowledge and embodiment systems legible through one cross-surface contract without creating new authorities.

The design rule is:

```text
Mary Core truth owners
  -> capability / knowledge / performance evidence
  -> read-only System Fabric projection
  -> Desktop / PWA / iPhone / future Stream+VR bodies
```

Nothing in this layer grants execution permission, promotes a model, rewrites memory, accepts retrieved text as truth, or lets a renderer become Mary.

## Capability contract

The System Fabric now normalizes capability evidence into explicit states:

- `demonstrated_ready`
- `demonstrated_permission_required`
- `historically_demonstrated_offline`
- `advertised_untested`
- `degrading`
- `evidence_only`

This is derived from the existing `SelfIntrospection.capability_evidence()`, node advertisement/readiness, local permission state, `CompetenceLedger`, approved procedure evidence and revision pressure.

A capability being advertised is not proof Mary can execute it. Demonstrated competence is not permission. Historical success is not proof a node is currently online.

## NOMAD-derived knowledge readiness

Public Project NOMAD releases reinforced several mechanisms Mary already owns: optional local AI/RAG services, Kiwix offline libraries, per-file activation, source/date citations, retrieval that can decline, explicit derivative lineage and deterministic RAG evaluation.

13.74 adds a cheap `evaluation_readiness` projection over Mary's existing `KnowledgeFabric` / `KnowledgeFabricEvaluator`:

- enabled pack count;
- indexed evidence count;
- stale local-index count;
- stale semantic-derivative count;
- whether deterministic regression is currently meaningful;
- exact evidence needed before claiming the substrate is current.

No scan or rebuild is triggered by status inspection.

## Riko-derived embodiment projection

The public MIT Riko repository demonstrates the value of a compact voice/ASR/dialogue loop, while later public product descriptions emphasize animated character presentation and desktop presence. Mary keeps the useful presentation lesson but not Riko's simpler prompt/history model as an identity or memory owner.

13.74 exposes one-character/many-bodies readiness across:

- Desktop;
- mobile web/PWA;
- native iPhone;
- stream/OBS;
- future VR/Unity.

`PerformancePacket` remains the canonical acting score. `DeliveryPlan` owns voice direction. `LiveScene` owns ephemeral scene context. Surface renderers may realize or safely degrade those cues; they do not persist identity, emotion, relationship, memory or world truth.

## Model experiment boundary

Existing `ModelExperimentLedger` evidence remains part of the same System Fabric. Model/LoRA candidates can be reviewed, benchmarked and marked trial-ready, but no experiment gains production routing authority from this convergence layer.

## Acceptance

13.74 is acceptable when:

1. every projected capability clearly distinguishes advertisement, availability, demonstrated evidence and permission;
2. stale knowledge derivatives/indexes prevent a clean evaluation-readiness claim;
3. Desktop/PWA/iPhone continue receiving the same System Fabric without a second backend;
4. embodiment readiness is read-only and references the existing PerformancePacket/surface contract;
5. model promotion, execution permission and truth acceptance remain false/explicit boundaries.
