MaryV2 — Diagnose & Restore Cloud LLM Routing Regression

We need to diagnose a regression in the CURRENT MaryV2 repository/runtime.

Do not redesign the architecture, replace the provider system, or broadly refactor Mary.

Current observed behavior

Mary Core 13.2 is online and the mobile/PWA successfully communicates with Core.

Mary’s distributed local-generation path is working.

When local-only generation is enabled, Mary reports that ordinary model-backed turns route through Ollama. The Windows capability node has previously successfully provided local Ollama inference.

However, after returning Mary to her normal/free-first generation route, ordinary conversational generation currently fails and Mary returns the deterministic fallback:

“Ugh—my language engines aren’t available right now. I’m still here, and my memory, relationship state, priorities, tools, and local systems are still running; I just can’t improvise a full conversational reply until a language model is available.”

This is a REGRESSION.

Cloud/provider generation worked previously.

Historically MaryV2 has used a provider/router architecture involving providers such as:

* Groq
* Gemini
* OpenRouter
* OpenAI where configured
* Ollama/local routing

The intended normal/free-first routing has historically included cloud/free providers before local fallback.

Do NOT assume those historical details are still exactly correct. Inspect the CURRENT repository and configuration.

Also observed:

A /last command sent through Mary Mobile did not produce provider diagnostics. It instead entered the ordinary conversational generation path and returned the same language-engine fallback.

Determine whether /last is actually supposed to exist in the current build before calling this a bug.
