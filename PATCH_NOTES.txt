MaryV2 Cross-Process Persistence Patch
======================================

Purpose
-------
Proves that Mary's durable episodic/semantic memory survives a completely new
Python interpreter process, while keeping direct Mary() construction free of
implicit reads/writes for tests and dependency injection.

Changes
-------
1. mary/runtime/application.py
   - Adds create_persistent_mary(...), a standalone Mary factory that enables
     the same durable memory behavior as the canonical Mary application.
   - Mary() remains intentionally side-effect-light.

2. scripts/verify_memory_restart.py
   - Spawns TWO separate Python processes.
   - Process 1 stores a temporary probe memory and exits.
   - Process 2 starts a fresh Mary application, reloads the same file, and
     recalls the probe.
   - Uses an OS temporary file, so data/memory/memory.json is not modified.

3. tests/runtime/test_persistent_mary.py
   - Regression coverage for create_persistent_mary and reload behavior.

Install
-------
Copy/merge the mary, scripts, and tests folders into the MaryV2 repository.
Do not overwrite .env or data.

Verify
------
python -m pytest tests -q
python -m scripts.run_diagnostics
python -m scripts.verify_memory_restart

Expected restart verifier ending:
RESULT: PASS
A completely new Python process reloaded and recalled Mary's memory.

Persistent one-line/debug usage
-------------------------------
Instead of:
    from mary.core.mary import Mary
    m = Mary()

Use:
    from mary.runtime.application import create_persistent_mary
    m = create_persistent_mary()

The canonical interactive runtime already persists automatically:
    python -m scripts.run_mary
