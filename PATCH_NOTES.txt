MaryV2 Self-Fact Provenance / Imagination Boundary Patch
========================================================

PURPOSE
-------
Make the distinction between Mary's durable self-state and temporary model
improvisation explicit and enforceable.

WHAT CHANGED
------------
1. Added mary/identity/self_provenance.py
   - canonical: authored/stable Mary facts
   - developed: durable state changed through explicit development/experience
   - situational: temporary model/dialogue imagination
   - unknown: absent self facts remain unknown

2. TurnMindState now carries self_provenance.
   Model output is explicitly NOT a persistence source.

3. Ordinary dialogue prompts now allow harmless hypothetical imagination while
   forbidding invented permanent self-claims.

4. Reasoning performs a conservative post-generation provenance audit for
   especially strong unsupported wording such as:
       "my favorite ... is ..."
       "I've always loved ..."
       "I'm a secret ..."

5. Reflection reuses the existing revision path when that audit fires. It asks
   the provider to keep the harmless scenario but soften/omit the invented
   permanent self-claim. A second LLM call is spent only on these exceptional
   drift cases.

6. No generated dialogue is written into Biography or Preferences simply
   because a provider said it.

7. Diagnostics now include:
       Identity: self_provenance

INSTALL
-------
Copy/merge the included mary and tests folders into your MaryV2 repo.
Do NOT overwrite .env or data.

TEST
----
python -m pytest tests -q
python -m scripts.run_diagnostics

LIVE TEST
---------
python -c "from dotenv import load_dotenv; load_dotenv(); from mary.core.mary import Mary; m=Mary(); r=m.process('Hey Mary, if you had a totally lazy spa day what would you do?'); print(); print('RESPONSE:', r.final_response); print(); print('META:', r.reasoning.metadata); print(); print('REFLECTION:', r.reflection.metadata)"

Look for:
    self_provenance_policy: model_output_is_situational_until_promoted

Normally:
    self_provenance_issue: None

If a provider invents a strong permanent self-claim, self_provenance_issue will
explain it and Reflection should revise the response without persisting it.
