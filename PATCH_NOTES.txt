MaryV2 Groq Conversation Efficiency Patch
=========================================

Purpose
-------
Fix normal Groq GPT-OSS conversation replies being cut off with
finish_reason='length' even when the visible reply is short.

Changes
-------
1. GPT-OSS requests now use Groq's max_completion_tokens parameter.
2. GPT-OSS defaults to reasoning_effort='low' for Mary's fast conversational lane.
3. GPT-OSS sets include_reasoning=False so reasoning is not returned to Mary as output.
4. Groq usage metadata records reasoning_tokens when the API reports them.
5. Normal conversation completion budgets are now:
   - brief: 400
   - medium: 800
   - detailed: 1200
6. MARY_GROQ_REASONING_EFFORT can override the default later (low/medium/high).

Validated in the provided MaryV2 codebase:
- 345 passed, 1 skipped
- diagnostics: 41/41 passed, Healthy=True

Install
-------
Merge the mary/ and tests/ folders into the MaryV2 repo.
Do not replace your real .env.

Test
----
python -m pytest tests -q
python -m scripts.run_diagnostics

Then rerun:
python -c "from dotenv import load_dotenv; load_dotenv(); from mary.core.mary import Mary; m=Mary(); r=m.process('Hey Mary, what would your perfect lazy day look like?'); print(); print('RESPONSE:', r.final_response); print(); print('META:', r.reasoning.metadata)"

Expected
--------
- provider: groq, unless Groq is rate limited and Mary falls through
- finish_reason: stop (ideally)
- prompt_tokens remains around the optimized ~3K range rather than ~7K
- completion no longer cuts off mid-sentence
- usage may now include reasoning_tokens
