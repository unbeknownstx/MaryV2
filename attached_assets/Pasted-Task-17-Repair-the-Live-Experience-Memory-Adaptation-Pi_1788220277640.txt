Specifically determine why explicit creator statements such as:

“I prefer technical explanations to begin with a short summary before the detail.”

and explicit feedback such as:

“That recommendation was too verbose. In situations like this, I prefer the shortest actionable answer first.”

produce growth experiences but zero preference candidates.

Important distinction

Do not make arbitrary temporary facts automatically semantic.

The desired behavior is governed/selective learning, not “store every sentence.”

A temporary fact such as:

“For this test my animal is otter and number is 47”

may reasonably remain dialogue-only unless reinforced/significant.

But an authenticated creator explicitly stating a durable interaction preference, especially when reinforced or supplied as corrective feedback, should reach the existing governed preference-evidence pipeline unless a documented safety rule deliberately prevents it.

If the current architecture intentionally requires repetition, confidence accumulation, evidence diversity, or review before promotion, preserve that. The defect is that production created no candidate at all, preventing governance from making that decision.

Determine whether those tests:

Do not merely add another test around the isolated subsystem. Add an integration test through the same MaryApplication creator-turn path production uses.

Desired repaired behavior

A normal authenticated creator interaction should be able to produce structured evidence when appropriate.

Examples:

Explicit durable preference

creator says:
“I prefer concise actionable answers first.”

Result may be:

experience → preference candidate → governed confidence/repetition process → eventual developed preference

It does not necessarily need immediate promotion after one statement.

Corrective feedback

creator says:
“That was too verbose. Give me the actionable answer first in situations like this.”

Result should at minimum create structured feedback/preference evidence that governance can evaluate.

Incidental temporary data

creator says:
“My temporary test number is 47.”

It is acceptable for this not to promote.

Model-authored assertion

Mary/provider invents:
“You prefer X.”

This must not become creator preference evidence without appropriate creator-origin evidence.

* provider output to rewrite creator preferences

CharacterSourcebook must remain authored/read-only authority.

Memory must remain lived evidence/history.

Developed self/preferences must remain governed mutable state.

Relationship state must remain separate.
