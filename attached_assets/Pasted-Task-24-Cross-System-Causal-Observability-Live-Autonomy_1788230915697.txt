1. Objective

Build a bounded, content-free causal trace that lets us answer:

“What happened because of this authenticated creator turn?”

For a successful turn, the trace should be able to show, where applicable:

Core instance
→ request
→ turn
→ provider attempts
→ response success/failure
→ experience
→ preference evidence/candidate/promotion
→ memory operation
→ relationship operation
→ attention event
→ autonomy evaluation
→ proposal
→ persistence/post-processing outcome

Not every turn will produce every object. Absence must be explicit and explainable.

⸻

2. Preserve privacy and boundedness

Do not expose:

* prompts;
* model output;
* memory contents;
* sourcebook contents/evidence;
* relationship text;
* creator preference text;
* tool arguments containing sensitive information;
* API keys;
* bearer tokens;
* node session credentials;
* environment secrets;
* raw provider exception bodies;
* upstream account/billing metadata.

Trace data should contain only bounded structural information such as:

* opaque IDs;
* stage names;
* subsystem names;
* status/disposition;
* counts;
* safe enums;
* sanitized failure categories;
* durations;
* hashes where already appropriate;
* timestamps;
* Core instance ID.

Retain existing trace/ring bounds. Do not create an unbounded telemetry log.

⸻

8. Live autonomy objective

Once causal tracing exists, produce one harmless live autonomy proposal through the real production Core.

The goal is to prove:

bounded trigger/event
→ attention
→ autonomy evaluation
→ proposal

and stop there.

The proposal must:

* be harmless;
* require no spending;
* require no destructive action;
* require no external message;
* require no filesystem mutation;
* require no tool execution;
* require no capability-node dispatch;
* remain proposal-only;
* preserve explicit creator confirmation as a separate later authority.

Good examples are non-consequential internal suggestions such as:

* suggesting that the creator revisit an unfinished task;
* proposing a harmless follow-up question;
* proposing a bounded internal review;
* surfacing a low-risk reminder-like idea without scheduling it automatically.

Do not manufacture emotionally manipulative or relationship-based triggers just to make autonomy fire.

⸻

9. Live autonomy causal proof

For the live proposal, record content-free:

* triggering request/turn/event ID;
* attention ID;

* proposal ID;
* proposal category;
* disposition/status;
* dedupe key or equivalent bounded identifier;

* whether confirmation is required;
* execution status.

Expected final execution state:

not executed

unless the system architecture defines another non-actioning terminal state such as proposed or pending_confirmation.

Verify no tool/capability request was actually executed.
