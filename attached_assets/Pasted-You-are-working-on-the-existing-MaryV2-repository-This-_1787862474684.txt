BACKGROUND

The current Mary constructor already creates:

The existing AutonomyRuntime already provides:

* start()
* stop()
* pause()
* resume()
* cycle()
* TriggerRegistry
* Scheduler
* ActionQueue
* passive intended actions
* explicit ActionPermission handling

Its safety boundary is intentional:

AUTONOMY MAY PROPOSE ACTIONS.
AUTONOMY MUST NOT EXECUTE EXTERNAL ACTIONS BY ITSELF.

Currently the autonomy object exists and is visible to other Mary systems, but the canonical MaryApplication does not start it and does not cycle it. Therefore autonomy is represented but operationally dormant.

GOAL

Connect autonomy into MaryApplication lifecycle so there is exactly ONE autonomy runtime belonging to the canonical Mary object.

Desired lifecycle:

-> existing mary.autonomy instance
-> autonomy starts once at canonical application startup/use

Successful Mary turn

-> realtime lifecycle completes
-> bounded TriggerContext is assembled
-> mary.autonomy.cycle(context)
-> resulting proposed actions remain passive/unapproved
-> compact autonomy result is attached to PipelineResult.metadata for observability

MaryApplication.close()
-> stop autonomy safely
-> preserve existing persistence/maintenance behavior

* a second AutonomyRuntime
